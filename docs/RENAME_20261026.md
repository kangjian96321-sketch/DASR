# DASR 命名迁移与替换说明

本次以已核对一致的 GitHub 20261025 发布包为基础，只更改名称、导入、调用和文档。
本地原项目和原 ZIP 均未修改，也没有替你提交到 GitHub。

## 1. 必须一起更名的入口与模块

| 旧路径 | 新路径 |
|---|---|
| `train_replay_comparison.py` | `train_DASR.py` |
| `train_pace_clean_linf_l2_patch.py` | `train_DASR_clean_linf_l2_patch.py` |
| `pace_aligned/`（整个模块目录） | `dasr_aligned/` |
| `pace_components.py` | `dasr_components.py` |
| `train_sseat_pace_aligned.py` | `train_sseat_dasr_aligned.py` |
| `train_crt_pace_aligned.py` | `train_crt_dasr_aligned.py` |
| `train_joint_pace_aligned.py` | `train_joint_dasr_aligned.py` |

Linux 区分大小写，主入口必须写为 **`train_DASR.py`**，不是 `train_dasr.py`。
没有保留旧入口兼容包装；不要只上传新文件而把旧入口也留在仓库中。
训练主入口在模块顶层没有启动训练的副作用，批量脚本与测试已经改用新名称。

以下也是联动修改，而不仅是改一个文件名：

- `ablation_config.py` 的方法展示标签和 `method_name()`；新日志前缀为 `dasr_*`。
- 主训练器、FAR、共享基线、绘图和所有入口的 `import`。
- `run_ablations.py`、`run_replay_study.py`、`run_far_source_modes.py` 的子进程入口。
- 汇总脚本的默认运行名；训练器默认运行名中的旧前缀。
- README、参数说明、环境名称和相关测试。Conda 配方新建的环境名为 `dasr` / `dasr-cpu`。

重命名按方法标识处理，不替换 `space`、`namespace`、`linspace`、`_evenly_spaced` 等普通词。
历史迁移记录和路径映射中的旧名字有意保留，用于说明要替换什么；运行代码不再依赖旧名字。

## 2. 两种顺序仍然保留

旧顺序：Clean → Patch → PGD-L2 → PGD-L∞：

```bash
CUDA_VISIBLE_DEVICES=0 python train_DASR.py \
  --dataset imagenette --backbone resnet18 --data-root ./data --batch-size 32 \
  --policy dtr --ablation full --replay-source-mode fg_adaptive_lazy \
  --far-monitor-size 500 --far-history-size 500 \
  --autoattack-samples 0 --autoattack-batch-size 4 --seed 42 --run-name dasr_forward_s42
```

新顺序：Clean → PGD-L∞ → PGD-L2 → Patch：

```bash
CUDA_VISIBLE_DEVICES=0 python train_DASR_clean_linf_l2_patch.py \
  --dataset imagenette --backbone resnet18 --data-root ./data --batch-size 32 \
  --policy dtr --ablation full --replay-source-mode fg_adaptive_lazy \
  --far-monitor-size 500 --far-history-size 500 \
  --autoattack-samples 0 --autoattack-batch-size 4 --seed 42 --run-name dasr_reverse_s42
```

也可以用 `train_DASR.py` 加 `--task-sequence clean pgd pgd_l2 patch` 指定新顺序，
但其默认输出根目录与独立逆序入口不同；建议始终明确 run-name，避免混用目录。
SSEAT/CRT 等方法自己的名称保留，只有原先含旧方法名的共享入口/模块改名；算法没有替换成 DASR。

## 3. 不变的机制与断点注意事项

保持 500/500、warm-up 后选 best、均值计入 0%、两种攻击顺序、四种 replay-source-mode、
LACD、DTR、F/G、缓存跨阶段保留、CRT ALR 对齐实现以及所有数值超参数。

但 **数值机制不变不等于旧 checkpoint 的元数据身份相同**：

- 主训练器协议字符串由 `far_pace_...` 改为 `far_dasr_...`。
- 四基线的版本字符串及 TRADES 描述性协议字段相应改名，可能改变配置签名。
- `method`、默认 run-name 和自动构造的输出目录可能变化。
- 网络 `state_dict` 参数键/结构不变，但本版没有提供旧原生断点的整套元数据迁移。

因此，当前服务器正在跑的实验不要覆盖代码，也不要改它的输出目录或签名。
让该实验继续使用原版本；下载本版到新目录用于后续实验。不要为了通过恢复校验而手动
篡改 checkpoint 中的签名。仅更名不要求把已完成的旧实验判作无效，应保留真实版本来源。
现有 Conda 环境无需仅因方法改名而重装；YAML 中的名称只影响以后创建的环境。

## 4. 如何更新 GitHub

推荐使用 Git 克隆仓库后在新分支中一次完成这组联动修改，等回归通过后再合并。
如果仓库仍与上次的 86 文件交付包一致，可以使用随交付提供的 `DASR_rename_20261026.patch`：

```bash
git clone https://github.com/kangjian96321-sketch/DASR.git DASR-rename-work
cd DASR-rename-work
git switch -c rename-to-dasr
git status --short
# 将补丁放在仓库目录外，例如此目录的上一级；先检查，不直接覆盖。
git apply --check ../DASR_rename_20261026.patch
git apply ../DASR_rename_20261026.patch
git diff --stat
git diff --check
git add -A
git diff --cached --stat
git commit -m "Rename method modules and entry points to DASR"
git push -u origin rename-to-dasr
```

在 GitHub 对该分支创建 Pull Request，检查 Actions 后再合并。
如果 `git status` 已有自己的修改，或 `git apply --check` 报错，请停止并先核对冲突；
不要使用 force/reset 覆盖。补丁只针对已核对的 20261025 快照，不是任意旧代码通用补丁。

网页上传方式也可以，但须同时完成“上传新路径、替换同名文件、移除旧路径”，并保留
`.github`、`.gitignore` 和 `.gitattributes`。**单纯 Upload files 不会删除旧路径。**
使用完整项目包解压到新文件夹更不易遗漏；不要把整个压缩包作为单个文件上传。
替换包中的 `replacement_files/` 内容对应仓库根目录，`REMOVE_OLD_PATHS.txt` 是需要
从仓库移除的旧源码路径清单，不是让你删除旧实验或服务器上的运行目录。

具体旧→新路径、需覆盖文件和新增文件见随包生成的 `rename_file_map.json`。
